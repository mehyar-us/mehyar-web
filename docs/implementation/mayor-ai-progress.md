- Tenant directory, current role checks, private conversation records, owner-managed business memory, activity, durable pause and trial/paid text reservations. Paid conversation access now checks the current plan, paid-through/grace/dispute state, release gates and activation evidence before dispatch and before delivery. Responses generated after access expires, a dispute opens or the business is suspended are withheld without charging the customer; provider attempts remain recorded. Included allowances reset on the subscription monthly anniversary, including annual plans; short-month and leap-year boundaries are handled in UTC. New-agent billing retains the first verified subscription usage anchor, and migration 0006 has been applied locally only. Durable provider-attempt limits bound failed and interrupted model calls separately from delivered customer credits. The model path requires explicit configuration; paid execution and external tool execution are not yet enabled.
- Three plan definitions ($349/$549/$899), 28 add-on definitions, 25 meters, 81 automation definitions, ten industry packs, and 18 protected product mappings. These definitions do not mean the executors or subscriptions are live.
- Separate new-agent billing implements setup/activation checkout, portal sessions, period-end cancellation, signed webhook ingestion, event and tenant leases, current-object reconciliation, renewals, payment-failure grace, and refund/dispute facts. Matching paid setup and plan-specific evidence gate activation. These paths pass isolated tests; commerce remains disabled until live evidence and configuration are established.
- Direct Google and Microsoft calendar/mail adapters implement bounded requests, recipient validation, scheduling conflict tokens, provider idempotency where supported, and change-subscription API calls. A server credential broker now renews both providers with encrypted token rotation, serialized refresh leases, compare-and-swap updates, scope reduction and safe reconnect after ambiguous/crashed renewals. The owner/manager calendar-list API uses it and rechecks access/pause before returning normalized choices. Calendar discovery and execution follow bounded server-side pagination, rechecking authority/pause for each page and reporting incomplete or looping directories without exposing cursors. Booking requires a complete directory. Automated writes and synchronization are not yet wired.
- Durable action reviews implement owner-only versioned policies, immutable typed reply/appointment proposals, explicit recipient/resource allowlists, actual scope checks, expiry, pause, current author/requester membership, UTC-day reservations and decision history. Policy changes invalidate old reviews. A gated dispatcher now executes Google/Microsoft replies and appointment creation, verifies paid access and provider readiness, reserves execution claims, checks original recipients/calendar ownership/availability and stores receipts. Exact duplicate effects are suppressed. Pre-dispatch failures require reapproval; dispatched failures and restarts become uncertain and cannot resend. The Approvals UI supports execution/receipts and owner-only appointment-policy creation using verified writable calendar choices, explicit attendee allowlists, daily limits, expiry, and review mode. Uncertain save retries preserve the exact policy ID and payload within the mounted form. Owners can list policies and edit their name, enabled state, recipient allowlist, expiry, preview/approval mode, daily action limit and escalation. Expiry edits are explicitly UTC and invalid recipient lists are rejected before saving. Version conflicts require refresh; disabling remains available while paused and for expired policies. Changes cancel pending approvals, without claiming cancellation of already dispatched effects. The local kill switch remains off, automatic workflows and reconciliation remain unfinished, and no live effect has been performed.
- Customer app implements signup selection, workspace creation/switching, conversation UI, memory, permissions, connections, usage/pricing display, pause, setup/activation checkout, billing portal, period-end cancellation and order history. Checkout buttons honor exact-plan readiness; return URLs never confirm payment. Unimplemented dashboard areas show honest unavailable/empty states. No customer data is fabricated at runtime.
- Git protection check covers 503 existing files, including payment routes/helpers, old migrations, old client, existing Workers, dependencies and deployment configuration. Synthetic agent events pass through the actual old webhook functions with no database/fulfillment effects.

## Evidence and limitations

Latest combined service verification: **160 tests passed across thirteen files** in local workerd, covering tenant isolation, signed OAuth fixtures, actual unchanged legacy handlers, catalogs, connector adapters, billing, model-call reservations, durable action reviews and credential renewal. TypeScript, the 503-file protection guard and independent Worker dry-run bundle passed. This includes regressions for different Stripe events arriving concurrently, setup-plan mismatch, refund ownership conflicts, revoked memberships, cross-business agent binding, failed model attempts, concurrent review limits, immutable action hashes, policy revision/expiry, author demotion and Google/Microsoft calendar scopes. Nineteen credential cases cover both providers, rotated/narrowed scopes, concurrent renewal, revocation/new consent during refresh, invalid grants, crash leases, bounded responses and normalized calendar reads withheld after pause/revocation. The signed OAuth fixture traverses policy creation, proposal, approval and history through the actual Worker API and proves wrong-origin decisions fail; it also prevents reuse of a failed refresh token through the identity-account fallback. Fifteen execution cases cover Google/Microsoft reply and appointment receipts, paid-access/readiness rejection, revoked grants, duplicate/concurrent requests, execution-day limits, overlapping bookings, busy calendars, owner pause, fresh approval after pre-dispatch failure, and uncertain outcomes after dispatch or restart. Six directory tests additionally cover per-page access checks, cursor loops, duplicate permissions, request/resource bounds, revocation and malformed authority; provider integration tests cover both cursor formats and booking from a later page. Provider requests in these cases use explicit fixtures; they do not prove live delivery. Nine additional cases verify monthly allowance boundaries, invalid/future anchors, monthly/annual paid chat, exact replay accounting, expired entitlement rejection, and stable usage anchors across later billing-date changes. Six paid-generation recovery cases cover expiry/dispute/suspension during inference, retry accounting across periods, the final shared credit under concurrent requests and the independent provider-attempt ceiling. Local `/api/health`, `/api/session`, `/api/auth/capabilities` and `/api/catalog` return 200/no-store; unauthenticated `/api/tenants` returns 401.

Frontend TypeScript/production build and **34 Chromium browser tests passed**, including accessibility checks on sign-in, conversation, billing and approvals. Authenticated browser tests use explicit network fixtures. Approval tests cover the exact reviewed hash, escaped untrusted content, paused rejection, staff/viewer restrictions, workspace switching and mobile layout. Four appointment-setup cases cover saved policy content, writable-calendar choice, incomplete results, manager restrictions, save retries, mobile layout, pause and workspace isolation; the form passes the accessibility check. Four saved-policy browser cases cover withdrawal while paused, preserving untouched permissions and concurrent-version conflict recovery, permission edits with exact retry payloads, and invalid recipient rejection; the editor passes accessibility checks. A runtime regression proves expired policies can be disabled idempotently while expired enabled policies remain rejected. Execution cases verify the exact approved hash, distinguish provider acceptance from delivery, and suppress resending after an uncertain outcome. Actual unauthenticated desktop/mobile captures use the running local Worker without interception; both providers correctly report unconfigured. The foundation production PWA shell was verified to reload offline with seven public assets cached and no API/auth/query/private data. These prove layout, contract behavior and shell caching, not live OAuth, mobile installation, payments or automation. Fixture screenshots are explicitly distinguished from the actual local page.

No production deployment, provider registration, price publication, purchase, email send, calendar change, phone provisioning, or legacy webhook replay has occurred. Live OAuth approval, actual scopes/accounts, scoped Cloudflare deployment access, Stripe account/price configuration, customer consent, cost telemetry and pilot evidence remain to be established. No authentication bypass exists in production code to substitute for that work.
